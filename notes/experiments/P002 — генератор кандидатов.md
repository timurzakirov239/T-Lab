# P002 — генератор кандидатов

[[СТАРТ|Карта проекта]] · [[notes/Эксперименты|Реестр]] · [[notes/experiments/P001 — локальный пилот|P001]]

## Вопрос и гипотеза

Почему retrieval P001 находит только 130/499 validation targets, и помогают
ли заранее заданные квоты повторов, более широкий профиль artist/album
или reciprocal rank fusion? Ожидаемые улучшения — гипотезы, а не результаты.

## Данные и протокол

Те же 64 пользователя и точные 1 848 запросов P001; никаких новых выборок.
Основной критерий — user-macro candidate recall на 499 validation-запросах;
дополнительно micro, counts, repeat/new, warm/cold, вклад источников.
Четыре варианта при K=100, без обучения моделей. Baseline должен совпасть
с P001 по точному порядку кандидатов на всех 1 848 запросах.

[[task_01_auto_features/configs/P002_PROTOCOL|Протокол до результатов]];
конфигурация `task_01_auto_features/configs/retrieval_002.json`.
События фильтруются в Arrow до передачи Python по p85; test не оценивается.

## Воспроизведение

Из корня проекта: `.\.venv\Scripts\python.exe -u task_01_auto_features/src/run_retrieval.py`.
Код и конфигурация коммитятся до запуска; SHA256 фиксируются в статусе.
Результаты: `task_01_auto_features/artifacts/retrieval_002/`.

Baseline совпал по item ID и порядку на всех 1 848 запросах P001; strata
сверены с прошлой историей. Загружены 270 429 development events после
Arrow-фильтра, replay наблюдал 270 367 до последнего запроса.

Runner 42,695 с; пик процесса 197,38 МиБ, минимум свободной RAM 2 146,05 МиБ;
лимиты не нарушены. Полные candidate records — 165,52 МиБ локально.
39 синтетических тестов прошли до запуска. Независимая
[[task_01_auto_features/research/P002_RESULT_REVIEW|проверка результатов]]
восстановила 7 392 записи, квоты/RRF/provenance и все метрики без расхождений.
Независимый reviewer не декодировал Parquet, проверил только bytes SHA256.

Repeat-heavy добавил 25 найденных запросов и потерял 2 относительно baseline;
пользователей с ростом/равенством/снижением recall — 17/33/2 из 52.
Это описательная парная разница; значимость не оценивалась.

## Ограничения и следующее действие

Development-выборка, один seed/когорта, ограниченные варианты; результат
retrieval не равен качеству ранжирования и не доказывает эффект признаков.
Repeat-heavy выбран как предварительный development-кандидат для будущего
общего retrieval. Он улучшает повторы, а новые треки остаются ограничением:
в объединённых depth200 pools только 13/165 новых целей baseline и 19/165
Affinity32. Улучшение coverage не объявляется улучшением NDCG/признаков.

Следующий этап P003 — микропрофиль и value-preserving оптимизация расчёта
признаков; затем измеряемая ступень 256 пользователей. Новый feature-код
пока не реализован и увеличение когорты не запускалось. P001 и P002
сохраняются для итогового отчёта; итоговый test не оценивался.
