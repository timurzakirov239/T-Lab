# P002 — протокольная проверка до результатов

Статус: preflight протокола и read-only review кода/config до запуска. P002 metrics не просмотрено и не рассчитано; реальные события и replay в ходе этого review не читались/не выполнялись.

Подтверждаю по текущему `src/run_pilot.py`, что P001 related sources используют top 5 artist/album профилей, а source candidate lists обрезаются до `max_candidates=100`. Протокол P002 сохраняет эти определения для exact equality anchor и не расширяет baseline через диагностическую глубину 200; глубина 200 полностью используется только RRF. Для Affinity32 явно отделены top32 профилей от первых 100 item в выдаче квот.

Протокол задаёт те же 1 349 train и 499 validation queries, проверку candidate IDs в точном порядке для всех 1 848 запросов P001, user-macro candidate recall как главный критерий, query-micro/counts и repeat/new, warm/cold с исходным знаменателем. Target-derived значения и P001 candidates закрыты от генераторов до завершения выдачи. Заданы Arrow-фильтрация до Python-level преобразований, strict prefix `< t`, source contribution/overlap отчёт, запрет test-оценки и обучения моделей, resource limits, failed-run handling и хеширование входов/кода/config.

## Read-only preflight runner-а

Проверены `src/run_retrieval.py`, `src/retrieval_candidates.py`, `configs/retrieval_002.json`, `configs/P002_PROTOCOL.md`, `src/pilot_storage.py` и синтетические runner-тесты. **Блокирующих несоответствий замороженному протоколу в текущей версии не найдено.** Реальный runner не запускал; event-файлы, строки p85+, P002 outputs и метрики не открывал.

- Loader читает только четыре event-колонки и делает `RecordBatch.filter(timestamp < validation_end)` в Arrow прежде `.to_pydict()`. Проверенная root-командой mixed-rowgroup synthetic sentinel-тестом логика исключает sentinel из `event_names`; сам тест review-ером повторно не запускался. Фильтр оставляет раннюю историю для построения user/catalog состояния, но исключает весь период p85+ из Python-level данных.
- Target, strata flags и P001 candidate list не передаются `RetrievalCandidateGenerator`; API генерации принимает только uid, timestamp и выбранную стратегию. Runner строит результаты всех четырёх стратегий до target-зависимого baseline equality check и вызова метрики. Same-timestamp группы остаются невидимыми до более позднего запроса через strict prefix.
- P002-Baseline source pools глубины 200 использует только первые 100 позиций; related profile depth 5 совпадает с P001, значит диагностические позиции 101–200 не меняют quota candidates. Affinity использует top32 и первые 100 item; RRF использует все четыре 200-deep pool и `c=60`. Baseline candidate sequence проверяется против сохранённого P001 query на всех train+validation строках до сохранения evaluation summary.
- Evaluation ограничен 499 validation queries; user-macro усредняет query hits внутри user, затем users; query-micro отдельно. Repeat/new и warm/cold агрегируются на той же исходной validation-выборке без фильтрации target misses. Pool source recall, pairwise overlap, actual quota source additions, popularity fallback и RRF source pools/contributions/ranks сохраняются в candidate records. Attribution popularity fallback исправлен в актуальном snapshot: fallback items добавляются в `selected_by_source` перед target attribution.
- Config содержит зафиксированные 64-user query counts, границы, K=100, depth200, profile depths 5/32, квоты, RRF=60, user-macro primary metric, лимиты 1100/150 MiB, `test_evaluation=false` и `model_training=false`. Runner сверяет boundaries с P001 metrics, query hash с checkpoint manifest, хеширует prepared files/config/protocol/source и сохраняет git commit; run directory не перезаписывается, failed status пишется в `finally`, завершённый output нельзя использовать повторно.

Осталось только проверить фактическое исполнение после разрешённого P002 run: baseline equality на всех 1 848 queries, число validation rows, итоговые source contributions и overlaps, ресурсы, hashes и отсутствие final-test scoring. По словам основного агента, текущие synthetic suite checks проходят; этот review не выдаёт их за независимо выполненный прогон.
