# P006 — однократная итоговая оценка работы 1

Протокол фиксируется до извлечения test-запросов и до test scoring. P001–P005
остаются development-историей. Победа над ручным набором не является условием
успеха исследования. После P006 запрещены подбор параметров и повторный test
по увиденным исходам; все исходы, включая failed, входят в отчёт.

## Популяция и время

Три непересекающиеся прежние когорты по64 UID: P001/P004, P005 seed20261026,
P005 seed20261027. Пользователей не заменять. Использовать все опубликованные
истории каждой когорты из уже сохранённых файлов. Test: timestamp>=23380165
до конца опубликованной истории; календарные даты/дни из RAW units не выводить.
Это временная оценка на ранее выбранных пользователях, не новые пользователи.
Первоначальная граница p85 была получена по timestamps P001. В P001 review
был документированный просмотр item_id/timestamp после p85 для проверки
кандидатов; test-метрики тогда не считались. Поэтому не утверждать абсолютной
изоляции исходной подготовки от всех test-полей. Новые test labels/метрики
не используются для решений о методе.

Для каждого UID равномерно выбрать до10 listen-запросов после границы,
исключив группы uid/timestamp с несколькими listen. Query seeds20361025,
20361026,20361027. Не фильтровать UID по активности/качеству и не выбирать
только retrieved targets. Сохранить число UID без test-запросов. Из таблицы
историй читать только uid,item_id,timestamp,event_type; остальные payload
не исследовать. Истории не обрезать и не сэмплировать события.

## Доступная информация и кандидаты

Online replay: перед запросом видны события строго timestamp<t, включая
предшествующие реальные test-события. События одного времени не видны друг
другу ни у одного пользователя. Target хранится отдельно от входов генератора
и признаков. Цель — следующий зарегистрированный listen в выбранный момент,
не клик после показа. Используются cohort-local каталог и статистики.

Оригинальный P001 CandidateGenerator, K100, квоты popular25/repeat25/artist35/
album15 и popularity fallback; target никогда не вставляется. Популярность
для baseline — прошлое число listen кандидата; ничьи score DESC/item_id ASC.
Прежние cohort-specific mapping snapshots сохраняются без расширения по test;
неизвестные связи имеют прежние defaults. Их временная доступность и полнота
50M относительно5B не установлены; доступность события на logged timestamp
остаётся допущением. New/cold и пропуски retrieval остаются в знаменателе.

## Итоговый метод и фиксированные сравнения

Основное сравнение — Auto_A2 против Manual UIDC66. Расширенный DSL выбран
как исследуемый метод: он имеет небольшое положительное ΔNDCG в обеих новых
development-когортах P005. Это решение по development, не доказательство
популяционного превосходства. Дополнительные фиксированные сравнения:
Manual I12, Auto_A1, Union, Popularity. Test не выбирает победителя для
последующего повторного test.

Каждая когорта использует собственные masks из замороженного P004/P005
selection_frozen.json: A1/A2/Union. Эти masks были выбраны по inner selection,
их не менять и не выбирать заново. A1 размеров16/62/8, A2 размеров8/197/64,
Union66/201/66. Переносится алгоритм с полученными внутри когорты masks,
не единый универсальный список признаков.

Финальное обучение каждой модели — на всех сохранённых development-query
blocks своей когорты (train+validation), original candidates и matrix206.
Только blocks с найденным target входят в fit, остальные train-пропуски
показать отдельно. Метки test в fit не попадают. Сохранённая matrix должна
быть complete, проверенной по hashes. Test baseline92 и auto206 строятся
последовательно; побайтное равенство всех A1/manual66 ячеек и входного порядка
обязательно до первого fit/scoring. Грамматика206/окна201117,670390,2011171,
short/half-life670390 неизменны.

CatBoost120/depth5/lr0.07/l2=5/Balanced/2threads, model seed20261025 одинаков.
Пять model masks на когорту, не более5 фактических fit; максимум15 на три.
Одинаковые masks переиспользовать только внутри когорты. Ожидается13 fits;
Popularity не обучается. Никакого поиска на test и добавления моделей после
результатов. Финальный evaluator использует legacy split='validation' как
техническое имя; evaluation_period='test' и final_test_evaluated=true явно
отличают P006 от development.

## Оценка, ресурсы и сохранение

Primary user-macro NDCG@20; дополнительно Recall@20,@10, candidate coverage,
repeat/new,warm/cold и все знаменатели. Показать каждую когорту и pooled
user-macro по всем пользователям с test-запросами с равным весом пользователя.
Номинальные192 не подставлять вместо фактического N. Объединение per-user
contributions не объединяет каталоги/истории моделей между когортами.

Для paired deltas Auto_A2−Manual UIDC показать описательный95% percentile
bootstrap CI:2000 resamples целых пользователей с возвращением, seed20261101,
отдельно для каждой когорты и pooled; сначала среднее по запросам пользователя.
Это условная неопределённость наблюдаемых пользователей, без повторного
обучения и без неопределённости выбора когорт/метода; не тест популяционной
значимости, не поправка на все исследованные варианты.

Последовательно три свежих child-процесса, RSS1100MiB/reserve150MiB. Failed
сохраняется, следующая заранее выбранная когорта всё равно выполняется;
бюджет не повышать, историю не урезать, пользователей не менять. Незавершённая
матрица не допускается к обучению. Ни одна папка запуска не перезаписывается.

До открытия test закрепить config, protocol, manifests input/source/masks
в Git. Global exclusive marker artifacts/p006_test_opened.json запрещает
повторное открытие этого финального протокола. Child допускается лишь по
родительскому marker и frozen hashes. Независимый пересчёт всех score outputs,
проверка hashes, компактный rank snapshot и portable verification обязательны.
В итоговый отчёт включить P001, отрицательные P003/Union и ограничения P005;
human verification источников не отмечать без подтверждения пользователя.
