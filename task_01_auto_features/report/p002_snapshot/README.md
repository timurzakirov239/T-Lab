# Сохранённая контрольная точка P002

Retrieval-only development-эксперимент `retrieval_002`, 25.10.2026.
Протокол зафиксирован коммитом `dc02423`, код исполнения — `dadc4ed`.
Тег принятого результата: `p002-retrieval-2026-10-25`.

В этой папке сохранены точные копии метрик/статуса, конфигурации, протокола
и независимой проверки. `validation_hits.csv` содержит 499 запросов с
идентификаторами пользователей, pre-query strata flags и четырьмя hit-флагами;
по нему можно независимо пересчитать user-macro/micro и срезы после Git clone.
Полные source pools и candidate IDs хранятся локально в
`artifacts/retrieval_002/candidate_records.jsonl` (около 166 МиБ), а их SHA256 —
в `metrics.json`. Большие raw outputs не отправлены в GitHub.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe task_01_auto_features/src/verify_retrieval_checkpoint.py
.\.venv\Scripts\python.exe task_01_auto_features/src/report_retrieval.py
```

Первая команда проверяет копии по манифесту и пересчитывает все 4×5 наборов
метрик; при наличии полных локальных outputs проверяет и их хеши. Вторая
пересоздаёт [отчёт](../P002_RETRIEVAL.md), CSV и график по замороженным метрикам.
Ни одна из команд не читает event-строки и не запускает обучение/replay.

Оригинальные результаты не редактировать. Любой новый поиск, изменение
квот или downstream ранжирование получает отдельный эксперимент.
P001 остаётся отдельной обязательной контрольной точкой итогового отчёта.
