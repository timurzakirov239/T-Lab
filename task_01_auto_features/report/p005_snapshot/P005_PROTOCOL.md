# P005 — повторение поиска признаков на двух новых когортах

Зафиксировано до чтения результатов 25.10.2026. Предыдущий development P004
сохраняется исторической контрольной точкой, не входит в новую выборку.

1. UID-only проход опубликованного Yambda-50M формирует отсортированную
   популяцию. Python random.Random(seed).sample выбирает 64 UID для seed
   20261026, затем 64 для 20261027 из оставшихся UID. Исключены ровно 64 UID
   P001/P004. Нет фильтра активности/качества. Обе membership записываются
   и хешируются до подготовки событий любой когорты; повторный отбор запрещён.
2. Полные опубликованные истории сохраняются Arrow напрямую. Development
   использует только timestamp <23380165, фильтр Arrow предшествует Python
   payload/statistics. Поздние payload не исследуются. Это полнота относительно
   опубликованного 50M, не заявление о полноте 5B. Метаданные — фиксированный
   snapshot с неподтверждённой временной доступностью.
3. RAW границы: train_query_start=9752280, train_end=20125775,
   validation_end=23380165. До30 train/10 validation запросов на пользователя,
   только группы uid/timestamp с одним listen. Seed запросов равен seed когорты.
   История строго timestamp<query; события с равным временем не видны.
4. Оригинальный P001 CandidateGenerator: K100, popular25/repeat25/artist35/
   album15; target не вставляется, кандидаты фиксируются до target-страт.
   Не применять repeat-heavy P002. Пропуски retrieval дают нулевые метрики
   в полном знаменателе; обучение условно на запросах с найденной целью.
5. Замороженные P004 source hashes обязательны. Грамматика206 идентична P004:
   A1=66 ручных UIDC, A2 добавляет140 выражений. Окна201117/670390/2011171,
   short/half-life670390. Baseline92 и auto206 строятся последовательно;
   все ячейки A1 должны совпасть побайтно float32 с manual66 до первого fit.
6. Алгоритм P004 повторяется независимо внутри каждой когорты. Inner cutoff —
   train timestamp p70 lower; fit<cutoff, selection>=cutoff. Pruning и importance
   только fit; full/top8/16/32/64/balanced32, dedup masks. Не более6 inner fits
   на семейство,28 total. Победитель по user-macro NDCG20, далее меньше столбцов,
   feature IDs. Все16 финальных masks (manual ablations, A1/A2/Union и исключение
   U/I/D/C) замораживаются до внешнего scoring. Совпадающие masks переиспользуются.
7. CatBoost120/depth5/lr0.07/l2=5/Balanced/2threads, model seed20261025 для обеих
   когорт. Он отличается от query sampling seed. Метрики@10/@20, primary
   user-macro NDCG20, также Recall, coverage, repeat/new и paired user deltas.
8. Последовательные свежие дочерние процессы; RSS1100MiB, резерв150MiB.
   Failed сохраняется, другая заранее выбранная когорта всё равно запускается.
   Не повышать бюджет, не обрезать историю и не пересэмплировать после failure.
   Новые исправления требуют нового run ID; пути не перезаписываются.
9. Независимый пересчёт по predictions и проверка hashes обязательны. Показать
   все исходы, размеры/знаменатели, выбранные выражения, время/память и paired
   deltas отдельно по когортам. Две небольшие development-репликации не дают
   основания заявлять популяционную значимость. Test не оценивается; итоговый
   метод и однократный test требуют отдельного протокола. Работа2 отложена.
