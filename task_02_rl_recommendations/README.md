# Работа 2. RL для последовательной рекомендательной модели

Статус: условие изучено, структура подготовлена. Эта работа начнётся после первой. Данные ещё не загружены, модели и экспериментальные результаты отсутствуют.

Исходное условие: [assignment.txt](assignment.txt).

## Что требуется

Нужно обучить модель на основе архитектуры GPT-2 для предсказания следующего объекта, отдельно построить и оценить модель вознаграждения, затем дообучить рекомендательную модель методом RL. Токены базовой модели — идентификаторы объектов.

Исследование должно показать, как RL влияет на релевантность, предсказываемое вознаграждение, разнообразие и повторяемость рекомендаций. Также нужно изучить генерацию нескольких шагов и обсудить связь выбранных сигналов с долгосрочными целями.

Положительный эффект RL по условию не обязателен. Нужны воспроизводимый эксперимент, содержательный анализ и отчёт.

## Предлагаемая постановка

Для начала — компактная GPT-2, обученная на последовательностях идентификаторов объектов, и вознаграждение по реально доступному сигналу отклика. Размер модели, длину контекста, каталог и объём выборки определим после осмотра данных и ресурсов.

Предварительный вариант RL — policy gradient с baseline для снижения дисперсии и KL-регуляризацией относительно замороженной базовой модели. Это предлагаемый метод для эксперимента; окончательный выбор и детали зафиксируем до обучения. Модель вознаграждения во время RL предполагается замороженной.

Гипотеза: увеличение оценки reward model может сопровождаться потерей релевантности или изменением распределения объектов. Исследуем, можно ли смягчить этот эффект настройкой вознаграждения и силы регуляризации. Наличие эффекта заранее не предполагается.

## План эксперимента

1. Проверить схему данных, порядок событий, доступные сигналы отклика и метаданные. Определить, какие события входят в историю и что считается следующим объектом.
2. Зафиксировать хронологическое разбиение и правила подготовки последовательностей. Все метки обучающих примеров должны быть доступны до соответствующей временной границы.
3. Обучить GPT-2 по next item prediction и оценить Recall@K и NDCG@K на заранее заданном каталоге кандидатов.
4. Обучить reward model на истории и рекомендуемом объекте. Оценить качество на отложенных реальных взаимодействиях; метрики выбрать по типу целевой переменной. При необходимости сравнить с простым предсказанием среднего отклика.
5. До RL зафиксировать протокол оценки, варианты вознаграждения, вычислительный бюджет, правила генерации и проверки checkpoints.
6. Провести RL-дообучение для ограниченного набора настроек. Сравнить исходную модель, регуляризованное RL и необходимые абляции, включая влияние KL. Отбор выполнять по validation.
7. Оценить генерацию на один и пять шагов. Исследовать сдвиг контекста, ошибки reward model, компромисс качества и вознаграждения.
8. После выбора конфигураций выполнить итоговую оценку на test и подготовить анализ ограничений.

## Важные условия протокола

- История каждого предсказания содержит только прошлые события. Окна с будущими целевыми событиями не должны попадать в обучение.
- Reward model не обучается на test; RL не оптимизируется по тестовым пользователям и контекстам из будущего периода. Правила использования данных обеими моделями опишем явно.
- Рост оценки той же reward model, по которой обучается policy, не служит независимым доказательством улучшения пользовательского опыта.
- В логах отклик наблюдается для состоявшихся взаимодействий или показов, в зависимости от набора. Качество reward model на таких данных не гарантирует точность для произвольных объектов, предложенных RL.
- Сгенерированный объект не считается фактическим действием пользователя. Добавление его в контекст на следующих шагах — моделирующее допущение, влияние которого нужно исследовать отдельно.
- Долгосрочные сигналы требуют горизонта наблюдения. Если используем возвращение пользователя или будущие взаимодействия как метку, исключим примеры без достаточного наблюдаемого будущего и учтём границы разбиения.

## Что измерять

| Аспект | Предварительная оценка |
| --- | --- |
| Релевантность | Recall@K, NDCG@K на одинаковых кандидатах |
| Reward model | Ошибка регрессии и/или метрики классификации по выбранной цели, анализ качества по группам |
| Оптимизация RL | Предсказанное вознаграждение, KL к исходной модели, стабильность обучения |
| Концентрация | Покрытие каталога и доля рекомендаций наиболее популярных объектов |
| Персонализация | Совпадение рекомендаций между пользователями |
| Повторения | Повторы внутри последовательности и доля уже знакомых пользователю объектов |
| Возможные побочные эффекты | Сдвиг длительности объектов, популярности и других доступных характеристик |
| Несколько шагов | Те же показатели отдельно на шагах 1–5 |
| Стоимость | Время, память и число обновлений модели |

Варианты вознаграждения после проверки полей: исходный сигнал отклика; его модификация со штрафом за повторы; доступный прокси продолжения взаимодействий. Интерпретацию каждого варианта нужно обосновать. Офлайн-эксперимент не установит причинное влияние на удержание без дополнительных предпосылок или онлайн-проверки.
